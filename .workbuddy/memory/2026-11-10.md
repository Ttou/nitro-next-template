# 2026-11-10

## 新增按钮级权限指令并接入业务页面

**权限键链路（重要约定）**：`shared/enums/permission.ts` 的 `PermissionEnum`（如 `sys.menu.system.user.create`）→ `db/seeders/sys-menu.seeder.ts` 中 `menuType: BUTTON` 的 `menuKey` → 后端 `@XltCheckPermission(PermissionEnum.XXX)` → `useUserStore.getInfo()` 筛出 BUTTON 菜单的 `menuKey` 存入 `permissions` → 前端 `v-permission` / `hasPermission()`。四处键名必须一致。

**新增/修改**：
- `web/directives/permission.ts`、`web/directives/index.ts`（新）：`v-permission` 指令（支持单个/数组、`v-permission:some` 任一匹配、`display:none` 隐藏且权限变化自动恢复）+ `hasPermission()` 工具函数。
- `web/main.ts`：在 `app.use(store)` 之后调用 `setupDirectives(app)` 全局注册。
- `web/store/useUserStore.ts`：`clear()` 补齐清空 `user / routes / permissions / infoRequested / homePath`，避免退出或切号时旧权限串号。
- 13 个 `web/views/biz/**/index.vue`：模板 `<el-button>` 用 `v-permission="PermissionEnum.XXX"`；`actionBar.buttons` 配置对象用 `show: hasPermission(PermissionEnum.XXX)`（依赖 `pageProps` 是 `computed`，故能跟随权限变化重算）。共 53 处绑定（29 模板按钮 + 24 行按钮）。

**踩坑**：`hasPermission` 内不可解构 Pinia setup store（`const { permissions } = useUserStore()` 会丢失响应性），必须保留 `store` 引用并访问 `store.permissions`，否则 `computed`/`watchEffect` 无法追踪权限变化。

**组件库事实**：`plus-pro-components` 的 `ActionBarButtonsRow.show` 支持 `boolean | Ref | ComputedRef | (row,index,button)=>...`，`table-action-bar` 会 `filter` 掉 `unref(show) === false` 的按钮，故传布尔值有效。

**已知后端缺口（本次未改）**：`server/apis/system/lang/lang.controller.ts` 全无 `@XltCheckPermission`；`user/lang` 的 `exportTemplate`、`importTemplate` 接口也无鉴权。前端隐藏按钮不等于接口安全，需后端补齐。对应地这些按钮（导入、下载模板、登录日志详情）保持未绑定权限。

**校验**：`npx eslint web/directives web/main.ts web/store/useUserStore.ts` 通过；`pnpm build:web` 通过（仅既有 chunk size 警告）；页面 lint 无权限相关新增错误（其余为仓库既有）。`tsc --noEmit -p tsconfig.app.json --ignoreDeprecations 6.0` 的报错均为仓库既有（.vue 声明、hooks 类型）。
